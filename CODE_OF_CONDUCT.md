# Code of Conduct

## Our Commitment

OrbitWatch is an open technical project intended for learning, experimentation, research, satellite communications, software engineering, signal processing, and cybersecurity-oriented portfolio development.

We are committed to providing a respectful, professional, and technically constructive environment for everyone who contributes to the project.

## Expected Behavior

Contributors are expected to:

* Be respectful and professional.
* Communicate clearly and constructively.
* Focus criticism on technical decisions rather than individuals.
* Welcome questions and different levels of experience.
* Provide useful technical reasoning when proposing changes.
* Respect project safety boundaries.
* Avoid intentionally introducing unsafe or destructive functionality.
* Protect private, sensitive, or identifying information.
* Clearly distinguish real-world operational data from sample or replay data.
* Follow applicable laws and regulations when working with radio hardware and satellite communications.

## Technical Safety

OrbitWatch is designed primarily as a receive-side satellite ground-station project.

Contributors must not intentionally introduce functionality that:

* Enables unauthorized RF transmission.
* Bypasses receive-only safety boundaries.
* Interferes with satellite, terrestrial, or other radio communications.
* Uses the project to disrupt communications.
* Exposes private network, radio, credential, or operational information.
* Presents synthetic development data as genuine live telemetry.
* Introduces malicious software or intentionally harmful code.

Hardware experiments must comply with applicable radio regulations and the rules governing the relevant frequency bands, licenses, and satellite services.

## Contributions

Good contributions include:

* Bug fixes.
* Tests.
* Documentation improvements.
* Protocol implementations.
* Signal-processing improvements.
* Telemetry improvements.
* Dashboard improvements.
* Performance improvements.
* Reliability improvements.
* Hardware integration work that respects the receive-only design.
* Security improvements.

Please explain the reason for significant architectural changes and include tests where practical.

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment or discrimination.
* Personal attacks.
* Threats or intimidation.
* Deliberate disruption of the project.
* Malicious code contributions.
* Deliberate exposure of credentials or private information.
* Deliberate introduction of unauthorized RF transmission capability.
* Deliberate interference with communications.
* Misrepresentation of replay/development data as live operational data.

## Reporting Issues

For security-sensitive issues, please follow the project's security guidance in `SECURITY.md` rather than publicly exposing details in an issue.

For general conduct concerns, open a private communication with the project maintainer when possible.

## Enforcement

Project maintainers may remove, reject, or restrict contributions that violate this Code of Conduct or the project's safety requirements.

The goal of enforcement is to maintain a professional technical environment while protecting contributors, users, radio systems, and the project itself.

## Scope

This Code of Conduct applies to:

* Source-code contributions.
* Documentation.
* Issues.
* Pull requests.
* Discussions.
* Project demonstrations.
* Other project-related communication.

By participating in the OrbitWatch project, contributors are expected to follow these standards.
